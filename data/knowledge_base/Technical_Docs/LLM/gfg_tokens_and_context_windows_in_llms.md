# Tokens and Context Windows in LLMs

> Source: https://www.geeksforgeeks.org/artificial-intelligence/tokens-and-context-windows-in-llms/

In Large Language Models (LLMs), tokens and context windows determine how text is represented and how much information a model can work with at a time. Understanding these concepts helps explain the limits of LLM inputs and outputs and how they handle longer text.
Tokens
A token is a unit of text produced by a tokenizer. Depending on the tokenizer, a token may represent a word, part of a word, punctuation, whitespace or other characters.
- Words: In many cases, a token corresponds to a single word (e.g., "apple," "run," "quick").
- Subwords: For languages with a rich morphology or for more efficient processing, words may be split into subword tokens. For example, "unhappiness" might be split into "un," "happi," and "ness."
- Punctuation: Punctuation marks like periods, commas and exclamation marks are also treated as individual tokens.
- Special Tokens: Some tokenizers also use special tokens for purposes such as marking sequence boundaries, padding, masking or other model-specific instructions.
Tokenization is the process of breaking down text into these smaller units. Different models use different tokenization methods.
A model has a maximum context window that limits how many tokens can be considered together. The actual input and output limits may also depend on the model and the API or application using it.
For example:
- GPT-4 has a context window of 8,192 tokens, with some versions supporting up to 32,768 tokens.
- Exceeding this limit requires truncating or splitting the text.
Input & Output Tokens
- Input tokens = prompt/context supplied to the model.
- Output tokens = tokens generated by the model.
- Both may be subject to model/application limits.
- The context budget may need to accommodate the relevant input and generated output depending on the system.
Tokens and words are not equivalent. A single word may correspond to one or multiple tokens, while spaces, punctuation and parts of words may also contribute to the token count. The exact number depends on the tokenizer.
Context Window
A context window is the maximum number of tokens a model can consider as context during a model invocation.
If a model has a 128K-token context window, its context can contain up to approximately 128,000 tokens, subject to the model and application’s specific limits.
LLMs use context windows to consider relevant tokens when generating text. Larger context windows provide more information, but they are still limited to a fixed number of tokens.

How Tokenization Affects Token Count
The same text can produce different numbers of tokens with different tokenizers. Words are not guaranteed to correspond to one token and spaces, punctuation and parts of words may also contribute to the token count.
Context Windows in Transformer Models
Modern LLMs commonly use token-based context windows. The maximum context size varies by model and determines how many tokens can be supplied as context for an invocation.
Example:
If a model has a 128K-token context window, the available context can contain up to approximately 128,000 tokens, subject to model/API-specific limits.

Trade-offs & Considerations
- Efficiency vs. Accuracy: Larger context windows provide more information but require more memory and processing.
- Memory Limitations: Large context windows increase memory usage and may require truncating or splitting long inputs.
- Long Inputs: Inputs exceeding the context limit may need techniques such as truncation or chunking.
- Sliding Windows: Sliding-window techniques can process long inputs in smaller sections but may lose information outside the current window.
